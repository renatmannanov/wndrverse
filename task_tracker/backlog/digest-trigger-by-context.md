# Backlog: дайджест по накоплению контекста (а не только по расписанию)

> Статус: backlog (не в MVP digest-scheduler)
> Появилось из: done/digest-scheduler/ (MVP — только расписание + ручной --now)

## Идея

Сейчас дайджест синтезируется по **расписанию** (sleep-loop, раз в день в
`WNDR_DIGEST_AT`) или вручную (`python -m digest.scheduler --now`). Это не учитывает
реальный поток: в один день в топик накапали 3 сообщения, в другой — 80. Расписание
шлёт дайджест в обоих случаях одинаково.

Альтернативный/дополнительный триггер — **по накоплению нового контекста**: как только
с момента прошлого дайджеста по топику набралось ≥ N новых фрагментов, синтезировать
и слать, не дожидаясь времени по расписанию.

## Почему фундамент уже есть

`artifacts` хранит `fragment_ids[]` каждого выпущенного дайджеста
(`core/store/fragments_db.py:save_artifact`). Значит «что уже вошло в прошлый дайджест
по топику» — известно из БД без отдельного state-файла:

```
new_since_last = fragments(topic) \ union(fragment_ids всех artifacts по этому topic)
если len(new_since_last) >= THRESHOLD → синтез
```

Это устраняет MVP-ограничение «пропущенный запуск не догоняется»: триггер смотрит на
накопленную дельту, а не на «сколько сейчас времени».

## Что надо будет сделать (эскиз, не делать сейчас)

- Функция `unseen_fragments(topic)` в store: фрагменты топика, не входящие ни в один
  artifact этого топика.
- ENV `WNDR_DIGEST_THRESHOLD` (напр. 25): сколько новых фрагментов копим до выпуска.
- В `digest/scheduler.py` — режим `--watch` (или отдельный loop), который периодически
  (раз в M минут) проверяет порог по каждому топику и дёргает `run_once` точечно по
  тем, что накопились.
- Возможна гибридная политика: «по расписанию ИЛИ по порогу, что раньше».

## Связанный future: `--angle` (уточнение угла дайджеста)

MVP-сигнатуры синтеза (`synthesize(topic, fragments, topic_type)`,
`_run_digest(topic, period, channel)`) принимают свободный `topic_hint`/`topic_type` —
новый аргумент «угол» (например «сделай дайджест только про запросы на менторство»)
прокидывается в `topic_hint` позже **без переделки ядра**. В scheduler сейчас есть
только `--now`; `--angle "..."` добавится как ещё один argparse-флаг, пробрасываемый
до `synthesize`. Делать вместе с этим триггером или отдельно — по ситуации.
