## Цель

Привести локальный корпус community-brain в порядок ДО продакшна: устранить
проблему дедупа (backfill и realtime строят разные `external_id`), мигрировать
старые 6530 фрагментов на единый ключ, спарсить ВСЕ топики WNDR через Telethon
(полный актуальный корпус), прогнать эмбеддинги. Результат — чистый единообразный
локальный корпус + исправленный код дедупа. Это вход для плана `prod-deploy`
(дамп этой БД поедет на VPS).

## Зафиксированные решения (НЕ обсуждаются в ходе работы)

1. **Единый `external_id` = `tg_{chat_id}_{msg_id}`** для backfill и realtime.
   Сейчас backfill: `wndr_{chat_name}_{msg_id}` (реально `wndr_WNDR chat_2265`);
   бот: `tgbot_{chat_id}_{msg_id}`. chat_id — стабильный, общий для обоих.
2. **Старые ключи — МИГРИРУЕМ SQL-апдейтом (вариант В), решение пользователя.**
   Локальная БД рабочая, эмбеддинги старых терять не хотим. ДВА пласта (детали в
   step_2): (а) ~6530 `channel_id IS NULL` ключ `wndr_WNDR chat_{id}` → проставить
   chat_id=-1002924475859 + ключ `tg_…`; (б) 4 шт `tgbot_-1003905781841_{id}`
   (raymann_agents, channel_id уже есть) → только переименовать `tgbot_`→`tg_`.
   Проверено: NULL-пласт даёт чистый числовой msg_id, нет коллизий, source=telegram.
   После апдейта новый backfill схлопнётся (ключи совпадут) — без дублей, без
   повторных трат на эмбеддинги. Числа — snapshot, сверять фактическим SELECT.
3. **Backfill — ВСЕ топики WNDR chat** (не только questions_to_*), решение
   пользователя 4.2. Список topic_id берём из `fetch_topics_list.py`.
4. **Знак chat_id.** Telethon `entity.id` = положительный (2924475859); в БД/у бота
   = `-100…` (`-1002924475859`). Везде приводим к `-100…`-виду.
5. **Telethon-backfill снимаем ЛОКАЛЬНО** (сессия `telegram_gather_dev.session`
   локальна). На прод корпус поедет дампом (план B), не повторным парсингом.
6. **PII не ломаем.** В OpenAI только `[#id]`+текст; имена локально. Не менять.
7. **Эмбеддинг — РУЧНОЙ прогон здесь** (стоп-точка `--estimate`). Автоматизация
   (systemd-timer) — в плане prod-deploy. Дайджест эмбеддинги НЕ использует
   (Pass1 — текстовый отбор LLM); нужны для near-dedup и будущего векторного поиска.
