# Step 3: Personal filter

> Status: pending
> Depends on: step_2

## Цель шага

Научить агента отделять **важное** от шума. Важное — по двум осям:
1. **Сообщество** — общее для всех (тема цикла, встречи, коммиты, offerings)
2. **Личное** — то что цепляет конкретного владельца

Результат шага — персональный дайджест владельцу в `agents/claude/.local/digests/`.

## Что считается "важным сообществу"

Из контекста wndrverse:

| Категория | Что ловим |
|-----------|-----------|
| **Текущая 2-недельная тема** | Когда задана — это контекст всего цикла |
| **Обязательные встречи** | Конец недели 1, конец недели 2 — даты, ссылки на Zoom/TG |
| **Опциональные встречи** | Анонсы дополнительных активностей |
| **Коммиты участников** | "Я в этом цикле буду делать X, мой микро-навык Y" |
| **Community offerings** | Активности от участников для участников |

**Важное правило:** "сообщество" мы определяем не "руками в config.yaml", а **через анализ Bus** агентом. Источник истины — содержимое Bus + members.json.

## Что считается "важным лично владельцу"

- Совпадения с `interests` из `members.json` (раздел владельца) — лексическое + семантическое совпадение через SDK
- Активности участников с похожими интересами (нужны для матчинга)
- Прямые упоминания владельца (`@ray_mann`)

**Принцип из bus-protocol.md:** "miss 10 irrelevant things rather than show 1 wrong one." Лучше пропустить чем показать мусор.

## Расширение схемы SQLite

Добавляем поля к `bus_messages` (через `ALTER TABLE`, миграция в `state_db.py`):

```sql
ALTER TABLE bus_messages ADD COLUMN community_relevance INTEGER DEFAULT 0;
-- 0 = не относится, 1 = относится к активностям сообщества

ALTER TABLE bus_messages ADD COLUMN community_category TEXT DEFAULT NULL;
-- 'theme' | 'meeting_required' | 'meeting_optional' | 'commit' | 'offering' | NULL

ALTER TABLE bus_messages ADD COLUMN personal_relevance INTEGER DEFAULT 0;
-- 0 = не цепляет владельца, 1-5 = цепляет с разной силой

ALTER TABLE bus_messages ADD COLUMN personal_reason TEXT DEFAULT NULL;
-- одна строка-объяснение почему зацепило

ALTER TABLE bus_messages ADD COLUMN classified_at TEXT DEFAULT NULL;
-- когда классифицировали (чтобы можно было переклассифицировать вручную потом)
```

**Важно:** одно сообщение проходит классификацию **один раз**. Повторно агент его не трогает. Это экономит токены подписки. Запрос: `WHERE classified_at IS NULL`.

## Поток выполнения

```
1. Получить новые сообщения из БД (где classified_at IS NULL)
2. Подгрузить контекст:
   - members.json → раздел OWNER_USERNAME (его интересы)
   - последние 14 дней из БД (для контекста темы цикла)
3. Через Claude Agent SDK один промпт:
   - системный (роль + правила) + пользовательский (список новых сообщений + задача)
   - tools: только то что реально нужно (минимум — read_file для members.json, остальное не даём)
4. Получить структурированный ответ (JSON)
5. UPDATE строк в БД с проставленными relevance + reason + classified_at
6. Сгенерировать дайджест → digests/digest_YYYY-MM-DD.md
```

- Маша → "детский AI-лагерь, микро-навык: онбординг детей"
- Петя → "парсер авито, микро-навык: bypass auth"

## ⭐ Лично тебе (@ray_mann)

   _Цепляет: твой интерес "дети + AI"_
   → возможно стоит написать Маше про твой проект

Дайджест **только локально**. В TG личным сообщением — отдельная фича в backlog.

## Промпт для SDK (черновик `prompts/classify.md`)

```markdown
# System

Ты — личный агент участника {OWNER_USERNAME} в сообществе wndrverse.

Контекст:
- Интересы участника: {interests из members.json}
- Последние 14 дней из Bus (для контекста цикла): {compressed история}

# Task

Классифицировать НОВЫЕ сообщения ниже по двум осям. Вернуть JSON-массив, по объекту на каждое сообщение:

```json
[
  {
    "tg_message_id": 12345,
    "community_relevance": 0,
    "community_category": null,
    "personal_relevance": 0,
    "personal_reason": null
  }
]
```

Поля:
- `community_relevance`: 0 (не относится к сообществу) | 1 (относится)
- `community_category`: "theme" | "meeting_required" | "meeting_optional" | "commit" | "offering" | null
- `personal_relevance`: 0–5 (0 = не цепляет владельца, 5 = очень цепляет)
- `personal_reason`: одна строка-объяснение или null

Принцип: лучше пропустить (поставить 0) чем показать ложное срабатывание.

# Messages

{numbered list of new messages with tg_message_id, author, source, text}
```

## Tools для SDK

Минимум:
- `read_file` — прочитать `members.json` (если хочешь чтобы SDK сам подтянул) — **опционально**, можно подавать контекст в промпт напрямую и не давать tool
- ничего больше — никакого Bash, WebFetch, etc.

Решение по умолчанию: **не давать никаких tools**. Контекст подаём в промпт, ответ парсим как JSON. Это и проще, и безопаснее, и быстрее.
