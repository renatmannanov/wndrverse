# Plan: Агент «Клод» — Claude Agent SDK через Max OAuth

> Status: pending
> Priority: medium
> Depends on: ничего

## Цель

Сделать первого автономного личного агента в `agents/claude/` — на **Claude Agent SDK через Max-подписку владельца** (OAuth, без API-ключа).

Агент:
- Свой процесс, свой запуск, свой Telegram-бот, своя локальная БД стейта
- НЕ переиспользует код из `curator/` (осознанное дублирование ради автономности)
- Триггерится по cron владельцем
- Читает Bus, опционально Telegram через Telethon, классифицирует, пишет дайджест себе и 0–2 строки обратно в Bus

Это **первый из трёх** автономных агентов. Дальше будут отдельными планами:
- `agents/openclaw/` — Sonnet API (другой план)
- `agents/hermes/` — Haiku API (другой план)

## Что не делаем (антискоуп)

- НЕ переписываем `curator/` — он остаётся как есть
- НЕ трогаем `agent-template/A/B/C` — они отключатся от логики позже сами
- НЕ создаём Опенкло и Гермеса в этом плане — они отдельные планы
- НЕ интегрируемся с общей БД сообщений сообщества (она существует, соединим в другом плане — см. `task_tracker/backlog/agents_read_community_db.md`)
- НЕ строим SaaS / managed-хостинг под чужими подписками — это нарушает Anthropic ToS
- НЕ делаем демона 24/7 — только cron-сессия

## Архитектурные решения (зафиксированы)

### 1. Локация и автономность

```
wndrverse/
├── agents/
│   └── claude/
│       ├── main.py              ← entrypoint, cron-сессия
│       ├── bus_client.py        ← свой клиент к Bus (read + write)
│       ├── tg_telethon.py       ← опциональный ридер каналов через Telethon
│       ├── state_db.py          ← обвязка над локальной SQLite
│       ├── prompts/
│       │   └── classify.md      ← промпт классификации сообщений
│       ├── .local/              ← gitignored: state.db, digests/
│       ├── .env.example
│       └── README.md            ← как развернуть
└── ...
```

Агент **не импортирует** из `curator/`. Если что-то переиспользуется концептуально (формат сообщений Bus, схема `members.json`) — это контракт через файлы/протокол, не через Python-импорт.

### 2. Источники чтения (выбор владельца)

| Источник | Когда | Как |
|----------|-------|-----|
| **Bus за 24ч** | всегда (дефолт) | через `python-telegram-bot`, `getUpdates` или `getChatHistory` к BUS_TOPIC_ID |
| **Telegram-каналы напрямую** | опционально | через Telethon, если владелец заполнил `TG_API_ID` + `TG_API_HASH` |
| **Общая БД сообщества** | пока НЕТ | существует у проекта, соединим в отдельном плане |

Логика: всегда читает Bus, и **дополнительно** читает каналы через Telethon если настроен.

### 3. Режим работы — cron-сессия

Владелец ставит cron на удобное время (например 6:00 перед своим утром):
1. Просыпается по cron
2. Читает Bus за прошедшие сутки (+ опционально каналы через Telethon)
3. Накапливает в локальной SQLite, помечает прочитанные
4. Через Claude Agent SDK классифицирует новые сообщения
5. Генерирует дайджест в `.local/digests/`
6. Пишет 0–2 строки в Bus (`agent_pick`, `agent_summary`)
7. Завершается. Hard-cap 5 минут.

Между запусками процесс **не висит**.

### 4. Где физически живёт

На устройстве владельца Max-подписки. `claude login` сделан там же. Варианты деплоя — в step_5.

### 5. Что агент читает

**Вход:**
- Bus (TG-supergroup, BUS_TOPIC_ID) за последние 24ч — всегда
- Каналы через Telethon — опционально
- `members.json` — для своих интересов (читается из репо)

**Что не читает (антискоуп):**
- Личные сообщения других участников
- Приватные группы в которых владелец не состоит
- Showcase (это уже куратор сделал)

### 6. Что агент пишет

**Личному владельцу:**
- Дайджест → `agents/claude/.local/digests/digest_YYYY-MM-DD.md`

**В Bus (через своего бота):**
- `[<owner>|agent_pick]` — что зацепило владельца сегодня (1 пункт, не каждый день)
- `[<owner>|agent_summary]` — краткая активность владельца за сутки (если есть)

Hard-cap: не больше 2 сообщений в день в Bus.

### 7. Anthropic ToS — границы (см. step_6 + research_context.md)

**Можно:**
- Личный агент на личной Max-подписке владельца
- Cron-триггер от человека (он сам себе настроил расписание)
- Чтение публичной TG-группы где владелец состоит

**Нельзя:**
- SaaS / managed-хостинг под чужими подписками
- Демон 24/7 без человеческого триггера
- Один OAuth-токен на нескольких людей

**Серая зона** — численного предела "ordinary individual use" Anthropic не публикует. 1 cron-тик/день, ~10–30 вызовов модели — укладываемся с запасом.
