# Шаг 3: Ограничение длины дайджеста (промпт + max_tokens)

> Зависит от: нет (первый слой длины; второй слой-обрезка — в шаге 2)
> Статус: [ ] pending

## Задача

Сделать так, чтобы синтез по умолчанию выдавал дайджест в пределах ~3500–4000
символов — первый (мягкий) слой ограничения длины. Второй (жёсткая страховочная
обрезка до 4096) уже в шаге 2.

### 1. Промпт `core/prompts/digest_synthesis.md`
Добавить в секцию «Правила» строку про объём:
```
- Уложись примерно в 3500–4000 символов. Лучше плотный и полезный дайджест, чем
  длинный пересказ. Если материала много — выбери самое важное, не перечисляй всё.
```
Не менять остальную структуру промпта (формат [#ID], секции 📌/👤/🔗/⭐).

### 2. max_tokens в Pass 2
В `core/brain/synthesis.py:_synthesize_fragments` (строка ~122-131) вызвать
`complete(...)` с `max_tokens`, чтобы был жёсткий потолок и со стороны API.
~4000 символов русского текста ≈ 2000-2500 токенов; берём запас `max_tokens=1500`
НЕДОСТАТОЧНО — ставим `max_tokens=2200` (≈ 4000 симв кириллицы с запасом).
```python
return complete(prompt, temperature=0.5, max_tokens=2200)
```
`complete()` уже принимает `max_tokens` (`core/llm/client.py:59`) — менять client
не нужно. Pass 1 (selection) НЕ трогаем — там короткий список id.

### Важно
- max_tokens — это ПОТОЛОК, не цель. Если дайджест короче — ок.
- Это мягкий слой: модель может слегка выйти за 4000 символов даже с max_tokens
  (токены ≠ символы). Поэтому страховочная обрезка в channels.py (шаг 2)
  обязательна — один слой не заменяет другой.

### НЕ делать здесь
- Не трогать two-pass логику отбора, не менять `complete()` в client.py.
- Не добавлять нарезку на части (не в MVP).
