## Цель

Realtime ingest-бот пишет в БД только 2 топика (`questions_to_men/women` — есть в
`topic_map.json`). Остальные **11 форум-топиков застыли на 3 июня**. Polling прошлое
не заберёт → разово добираем через **telegram-gather (Telethon userbot, локально)**,
заливаем в прод-БД на VPS через scp + loader. Дедуп по `external_id` страхует от
двойников.

## Решения этой сессии (апрув пользователя 2026-06-05)

- **`--limit 700`** на каждый топик. `iter_messages` идёт от свежих к старым →
  700 свежих гарантированно покрывают всё после 3 июня (проверено по коду
  fetch_topic.py:70). Болтливые топики (boltalka 3668, offerings 2008, daily 1981,
  requests 954) — если 700 не докопают до стыка 3 июня, добьём повторным прогоном
  без лимита (дедуп делает повтор безопасным).
- **Заливка через scp на VPS** (не туннель). Порт БД :5434 остаётся закрытым;
  loader работает в том же venv/.env, что и бот → идентичная нормализация
  external_id, ноль шанса на рассинхрон ключей.
- **Бэкап таблицы fragments** перед заливкой (откат). `.sql` с PII → удалить после
  проверки.
