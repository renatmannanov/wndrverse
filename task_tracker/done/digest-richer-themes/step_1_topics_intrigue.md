## Задача

К каждой hot-теме добавить ОДНУ цепляющую строку-интригу (крючок), генерируемую
тем же ОДНИМ LLM-вызовом, что и название. Если интрига пустая/ошибка — тема
рендерится как раньше (graceful degradation, рендер не падает).

### Контракт между слоями (не нарушать разделение)

- `topic_label.md` (промпт) — возвращает СТРОГО JSON: `{"name": "...", "intrigue": "..."}`.
  Один вызов, обе строки. PII: на вход идут ТОЛЬКО тексты сообщений (как сейчас),
  никаких sender_id/имён.
- `core/brain/topics.py` — парсит JSON, кладёт в результат поля `name` И `intrigue`.
  Возвращаемый dict темы становится: `{name, intrigue, msgs, anchor_channel_id,
  anchor_external_id}`. Парс fail-soft: невалидный JSON / пустой ответ → `name="тема"`
  (как сейчас) и `intrigue=""`.
- `delivery/topics_render.py` — печатает строку-интригу ОТДЕЛЬНОЙ строкой между
  названием и ссылкой, ТОЛЬКО если `intrigue` непустая. Рендер ничего не знает про LLM.

### Точные правки

1. **`core/prompts/topic_label.md`** — переписать: просить JSON с двумя полями.
   - `name`: цепляющее короткое название (2–5 слов), как сейчас — но допускается
     вопрос/конфликт (например «Claude слишком умный для бытовухи?»).
   - `intrigue`: ОДНА строка ≤ ~140 символов — крючок, ради которого хочется
     открыть тред: в чём соль/спор/неожиданный поворот. НЕ пересказ всех деталей,
     НЕ список участников, без имён. Намекни на развязку, не раскрывая полностью.
   - **Качество крючка (моё #1 — это ГЛАВНАЯ цель фичи, не наличие строки):** дать
     в промпте 1-2 few-shot примера ХОРОШЕГО vs ПЛОХОГО крючка, иначе gpt-4o-mini
     скатится в ленивый пересказ «Обсуждали X, пришли к Y» — формально интрига есть,
     цель (захотелось тыкнуть) не достигнута.
     - ПЛОХО (пересказ): «Обсуждали выгорание, делились опытом восстановления.»
     - ХОРОШО (крючок): «Один совет сработал у всех, кроме одного — и спор не утих.»
     Крючок = вопрос / конфликт / недосказанность, НЕ «обсуждали…/делились…».
   - Жёстко: «Верни ТОЛЬКО JSON-объект `{"name": "...", "intrigue": "..."}`,
     без текста до/после, без markdown-fence».
   - **name держать ЖЁСТКО 2–5 слов** (защита от дрейфа, моё #4): max_tokens вырос
     до 200, ничто кроме промпта длину name больше не сдерживает.
   - Вход `{sample_texts}` остаётся как есть (только тексты).

2. **`core/brain/topics.py`** (функция `build_topics`, блок «LLM names»):
   - Поднять `max_tokens` с 30 до **200** (ревью #6: НЕ «~120» — кириллическая интрига
     ~140 симв ≈ 70-90 токенов + name + JSON-синтаксис не влезут в 120 → обрезанный
     JSON → молчаливый fail-soft. Зафиксировать ОДНО число 200, без тильды).
   - **Парс — ОТДЕЛЬНЫЙ tolerant-парс ОБЪЕКТА, НЕ `_parse_json_array` (ревью #1, блокер).**
     `_parse_json_array` (synthesis.py:290) заточен под МАССИВ: его fallback ищет
     `s.find("[")` / `rfind("]")` — для объекта `{"name":...,"intrigue":...}` он не
     найдёт ничего. Написать свой: снять возможный ```json fence (тот же приём, что
     `_parse_json_array` строки 297-303 / критик в commit 754cea2), затем `json.loads`,
     взять `name`/`intrigue` из dict. На любой fail (не-JSON, пустой ответ, не dict,
     нет ключей) → `name="тема"`, `intrigue=""`. НЕ переиспользовать `_parse_json_array`.
   - В итоговый dict темы добавить ключ `'intrigue': intrigue`.
   - Сохранить fallback `name or "тема"`.
   - **Дрейф name (моё #4):** name теперь приходит из JSON с max_tokens=200 (раньше
     голая строка, 30 ток. вынуждали краткость). Чтобы названия не поползли в длину —
     потолок «2–5 слов» держать ЖЁСТКО в промпте (см. п.1). В шаге 3 сверять глазами
     не только наличие интриги, но и что НАЗВАНИЯ не раздулись/не изменили формат.
   - **Модель + стоимость (моё #2):** зафиксировать в коде/комменте, какая модель
     генерит `topic_label` (сейчас gpt-4o-mini). Δтокенов: было ~30 на тему, стало
     ~200 → ×N тем за вызов. Прикинуть на типичный /topics (10 тем × 200 ток.) и
     отметить в progress.md. «Прод не трогаем» ≠ «прод не заденет»: если /topics
     зовут вручную в проде — это ближе к тому же TPM-потолку (см. инцидент в progress.md).

3. **`delivery/topics_render.py`** (`render_topics`):
   - После строки `{emoji} {name} (N сообщений)` — если `t.get('intrigue')` непустая,
     добавить строку `   {intrigue}` (с тем же отступом, что ссылка), ПЕРЕД ссылкой.
   - Если intrigue пустая → строку не печатать (старое поведение).
   - НЕ менять формат названия, эмодзи, ссылки, plural.

4. **Докстринги (мелочь ревью):** обновить устаревшие докстринги в `topics.py` /
   `topics_render.py`, где описан контракт dict темы без `intrigue` — добавить ключ.
