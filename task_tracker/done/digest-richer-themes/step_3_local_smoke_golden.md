## Задача

Обкатать ОБА режима локально на реальных данных (boltalka), сравнить вывод
до/после глазами и через golden-set. Прод НЕ трогаем (на gpt-4o-mini из-за TPM).

### Точные операции

1. **Полный прогон юнит-тестов** — ничего не сломалось:
   ```bash
   cd /c/Users/renat/projects/wndrverse
   python -m pytest -q
   ```
   Все зелёные. Если красное — чинить в шагах 1/2, сюда вернуться.

2. **Поднять локальную БД** (если не поднята):
   ```bash
   docker compose up -d db
   ```
   (нужны DATABASE_URL + OPENAI_API_KEY в .env)

3. **Golden BASELINE снять ДО изменений было невозможно** (правки уже сделаны в
   1/2). Поэтому здесь делаем так:
   - Если в `tests/golden/snapshots/*.txt` уже есть эталоны от прошлой задачи
     (digest-output-quality) — переснять как `--baseline` НЕЛЬЗЯ (код уже новый).
     Вместо этого: переснять текущие `--check` против старых эталонов, чтобы
     УВИДЕТЬ diff (расхождение ОЖИДАЕМО — мы меняли блок тем):
     ```bash
     python -m tests.golden.run --check || true   # покажет РАСХОЖДЕНИЕ по /summary-кейсам
     ```
   - **Как читать расхождение (ревью #7 — критерий «ожидаемое vs аварийное»):**
     - ОЖИДАЕМО (норма, не паниковать): расхождение в /summary-кейсах в блоке
       ГЛАВНЫЕ ТЕМЫ — мы намеренно меняли этот блок. /topics golden НЕ покрывает
       вообще (проверяется глазами через smoke-команду ниже, п.4).
     - АВАРИЙНО (поломка, чинить в 1/2): пустой текст; голые `[@N]` в выводе;
       обрыв на полуслове; пропали блоки КТО ЧТО / ЗАПРОСЫ; изменился блок, который
       НЕ трогали.
   - Затем переснять новые эталоны и просмотреть глазами, что блок ГЛАВНЫЕ ТЕМЫ
     стал содержательным, а КТО ЧТО / ЗАПРОСЫ не деградировали:
     ```bash
     python -m tests.golden.run               # перезапишет <name>.txt новыми
     ```
   - Глазами открыть 1–2 свежих snapshot и сверить с прежним выводом (git diff не
     сработает — snapshots gitignored; сравнивать с .baseline.txt если он есть от
     прошлой задачи, иначе глазами по памяти/скрину).

4. **Smoke /topics** на 1m с интригой:
   ```bash
   python -m delivery topics --topic boltalka --period 1m --limit 8
   ```
   Проверить глазами:
   - **Качество крючка (моё #1 — ГЛАВНЫЙ критерий приёмки, не наличие строки):**
     интрига = вопрос/конфликт/недосказанность, ХОЧЕТСЯ тыкнуть. БРАКОВАТЬ ленивый
     пересказ «Обсуждали…/Делились…» — формально строка есть, цель не достигнута.
     Если крючки на boltalka выходят пресными → ДОКРУТИТЬ промпт `topic_label.md`
     (усилить few-shot), это план Б, а не «принять как есть».
   - **Дрейф названий (моё #4):** сверить НАЗВАНИЯ до/после — после JSON+max_tokens=200
     они не должны раздуться за 2–5 слов или сменить формат. Раздулись → ужать промпт.
   - Под каждой темой ОДНА строка-крючок между названием и ссылкой; хотя бы у части
     тем интрига непустая; пустые интриги не ломают рендер (старый формат).

5. **Smoke /summary** на 1m с содержательными темами:
   ```bash
   python -m delivery digest --topic boltalka --period 1m
   ```
   Проверить: блок ГЛАВНЫЕ ТЕМЫ — 1–2 предложения сути на тему; КТО ЧТО / ЗАПРОСЫ
   на месте; нет голых `[@N]` (имена подставились); текст < 4096 символов.

6. **Длина — явная проверка (ревью #5):** ИЗМЕРИТЬ длину текста /summary (не «на глаз»):
   ```bash
   python -m delivery digest --topic boltalka --period 1m | wc -m   # < 4096
   ```
   Убедиться: `_looks_truncated` не логирует warning; текст после подстановки имён
   < 4096. boltalka может НЕ выявить overflow (зависит от числа участников) — если
   близко к потолку, ОТМЕТИТЬ риск в progress.md (не решаем MAX_FRAGMENTS/MAX_TOKENS
   здесь — out-of-scope, только фиксируем сигнал). В /topics длина не лимитирована
   жёстко — проверить, что вывод не абсурдно длинный для --limit 8.

- [ ] В progress.md записаны: примеры до/после (1–2 темы), Δтокенов /topics,
      близость к потолку длины (если есть), найденные нюансы.
