## Контекст для агента

Делаем темы «полнее» в ДВУХ режимах дайджеста РАЗДЕЛЬНО (не смешивая). Референс —
саммари другого бота (техночат): полные темы с описанием + ссылка. Берём ИДЕЮ

не техночат; блоки «ссылки/инструменты» там будут пустыми — их НЕ добавляем).

### Решения пользователя (2026-06-18)
- /topics: цеплять = название + ОДНА строка-интрига (крючок, не пересказ) + ссылка.
- /topics: ОДИН LLM-вызов возвращает И название, И интригу (не два вызова).
- /topics: пустая/ошибочная интрига → тема рендерится как раньше (graceful, не падать).

  сути на тему). КТО ЧТО и ЗАПРОСЫ НЕ трогать.

### PII-контракт (НЕ нарушить)
- В OpenAI уходят ТОЛЬКО тексты сообщений и анонимные `[@N]`. Имена/`@handle`/
  sender_id подставляются ЛОКАЛЬНО (topics: имён вообще нет в выводе; summary:
  humanize_author_refs). Новые промпты НЕ должны просить/принимать имена.
- В блоке ГЛАВНЫЕ ТЕМЫ /summary `[@N]` ЗАПРЕЩЁН (участники — в КТО ЧТО) → содержание
  тем PII-контракт не затрагивает.

### Tolerant JSON parse (образец)

## Learnings
- Промпт идёт через `template.format` → литеральные `{`/`}` в JSON-примере промпта
  ОБЯЗАТЕЛЬНО экранировать как `{{`/`}}`, иначе KeyError на `.format`. Проверено
  отдельным smoke (`t.format(sample_texts=...)`).
- `wc -m` на UTF-8 снапшоте НЕ равен длине в символах Telegram (кириллица многобайтна) —
  мерить длину дайджеста надо `result['text']` len (runner) или PS `Measure-Object -Character`.
