## Критичное (исполнитель потеряет часы или получит неверный результат)

### 1. BUS_TOPIC_ID и SHOWCASE_TOPIC_ID — URL в .env, int в коде

**Где:** step_1_infra.md (`.env` структура) vs step_3_agents.md (`bus.py`) и step_4_curator.md (`main.py`)

**Что не так:**

step_1_infra.md задаёт .env:
```
BUS_TOPIC_ID=https://t.me/c/3968221945/3
SHOWCASE_TOPIC_ID=https://t.me/c/3968221945/1
```

step_3_agents.md `bus.py` и step_4_curator.md `main.py` оба делают:
```python
BUS_TOPIC_ID = int(os.getenv("BUS_TOPIC_ID"))
SHOWCASE_TOPIC_ID = int(os.getenv("SHOWCASE_TOPIC_ID"))
```

`int("https://t.me/c/...")` → `ValueError` → полный крэш при запуске агентов и куратора.

**Потери:** Шаги 3 и 4 не запустятся вообще. Исполнитель будет разбираться откуда берётся ошибка — 30-60 минут, особенно если не смотрел step_1 внимательно.

---

### 2. BOT_TOKEN — имя переменной разное в .env и в коде

**Где:** step_1_infra.md (`.env` структура) vs step_3_agents.md (`bus.py`) и step_4_curator.md (`main.py`)

**Что не так:**

step_1_infra.md задаёт .env:
```
CURATOR_BOT_TOKEN=8771986558:...
AGENT_ONE_BOT_TOKEN=8763901915:...
```

Переменной `BOT_TOKEN` в .env нет вообще. Но `bus.py` и `main.py` читают:
```python
BOT_TOKEN = os.getenv("BOT_TOKEN")
```

Результат: `BOT_TOKEN = None` → `Bot(token=None)` → ошибка авторизации Telegram при первой попытке постить.

**Потери:** Постинг в Bus и Showcase не работает, причина не очевидна — `None` передаётся молча. Поиск причины: 15-30 минут.

---

### 3. AGENT_ID_AI и AGENT_ID_COMMUNITY — нет инструкции по записи в .env

**Где:** step_3_agents.md (критерии) vs step_4_curator.md (`main.py`)

**Что не так:**

Критерий step_3: "2 агента созданы в Anthropic cloud (ID сохранены в .env)" — написано что сохранить, но не написано под какими именами.

Тестовая команда в step_3 использует `'AGENT_ID_HERE'` — плейсхолдер без подсказки.

step_4_curator.md `main.py` читает:
```python
AGENT_IDS = {
    "ai": os.getenv("AGENT_ID_AI"),
    "community": os.getenv("AGENT_ID_COMMUNITY"),
}
```

Если исполнитель сохранит IDs под другими именами (что вероятно без явного указания) — `AGENT_ID_AI = None`, агенты молча пропускаются (`if not agent_id: continue`), шаг 4 отработает без ошибок, но Bus будет пустой.

**Потери:** Шаг 4 запустится, покажет "Агенты написали в Bus: 0 сообщений", исполнитель будет отлаживать агентов думая что проблема в коде агентов — 30-60 минут.

## Важное (исполнитель потеряет >5 минут на разбирательство)

### 4. Нет инструкции по созданию curator/ как Python-пакета

**Где:** step_2_reader.md, step_3_agents.md, step_4_curator.md — все импортируют `from curator.reader import ...`

**Что не так:**

Ни один шаг не упоминает создание `curator/__init__.py`. Без него `from curator.reader import ...` завершается `ModuleNotFoundError` если запускать из корня проекта.

Это не очевидно для того кто просто создаёт файлы по шагу и запускает команды.

**Потери:** 10-20 минут на поиск причины импорт-ошибки.

---

### 5. Сценарий 1 не реализован, но step_5 требует его протестировать

**Где:** step_4_curator.md (критерии) vs step_5_test.md (Тест 2)

**Что не так:**

step_4_curator.md критерий: "Сценарий 1 задокументирован (голосование в Bus) — даже если не реализован"

Но step_5_test.md Тест 2 описывает конкретные шаги проверки сценария 1 и включает его в критерии готовности шага 5:
```
- [ ] Тест 2 или 3 выполнен (хотя бы один)
```

"Хотя бы один" снимает блок, но исполнитель потратит время на разбирательство: Тест 2 требует "модифицировать промпты агентов" — это фактически новый код, но шага для этого нет.

**Потери:** 10-15 минут на понимание что Тест 2 требует дополнительной реализации которой нет в плане. Риск что исполнитель попытается реализовать его на месте без плана.

---

### 6. GROUP_CHAT_ID — есть в .env шаблоне, нет инструкции как получить

**Где:** step_1_infra.md

**Что не так:**

`GROUP_CHAT_ID=...` присутствует в шаблоне .env, но инструкция "Как получить TOPIC_ID" есть, а аналогичной инструкции для `GROUP_CHAT_ID` нет. Метод получения CHAT_ID супергруппы (через getUpdates или другой способ) не описан.

**Потери:** 10-15 минут на поиск способа получить числовой chat_id супергруппы (он отличается от обычного формата и требует отдельного шага).
