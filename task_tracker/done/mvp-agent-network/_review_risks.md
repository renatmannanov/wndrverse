## Критичное (только [CONFIRMED] и [LIKELY])

### 1. Токены бота в открытом виде в плане [CONFIRMED]
**Шаг 1, step_1_infra.md, строки 23–24.**
В `.env структура` в тексте шага вписаны реальные токены ботов:
```
CURATOR_BOT_TOKEN=8771986558:AAEr4SVzpLvFjd36NSiOJND_RJc_q60uEuI
AGENT_ONE_BOT_TOKEN=8763901915:AAGiwgM4s0Kk64CU7kWvvix_ukecB-dsQ7M
```
Файл находится в `task_tracker/todo/` — в git (согласно CLAUDE.md: "task_tracker/ ← планы (в git)"). Если репозиторий публичный (open-source по CLAUDE.md: "Open-source community networking tool") — токены уже утекли. Даже если приватный — они зафиксированы в истории коммитов навсегда, если шаг был закоммичен.
**Необратимо:** токены нужно отзывать через @BotFather и перевыпускать.

### 2. Telethon сессия — авторизация требует интерактивного ввода [CONFIRMED]
**Шаг 2, step_2_reader.md, строки 31–32.**
`TelegramClient(SESSION, API_ID, API_HASH)` при первом запуске запросит номер телефона и OTP-код в интерактивном режиме (stdin). В CI, автоматическом или headless-окружении это заблокирует выполнение. Критерий готовности шага 2 требует "`.session` файл есть" — но план не описывает как именно пройти авторизацию. Агент-исполнитель может зависнуть или сгенерировать `.session` файл с пустыми данными.

### 3. Managed Agents API — бета-флаг несуществующей версии [LIKELY]
**Шаг 3, step_3_agents.md, строки 62–64, 80–81.**
Код использует `betas=["managed-agents-2026-04-01"]`. На дату знаний модели (август 2025) такого бета-флага не существовало. Если API Managed Agents не запущен или флаг неверный — `create_agents()` и `run_agent_session()` вернут ошибку 400/404. Весь шаг 3 и всё последующее встанет. В плане нет fallback и нет инструкции как проверить актуальный список бета-флагов перед запуском.

## Важное (только [CONFIRMED] и [LIKELY])

### 4. `run_agent_session` — синхронный вызов внутри `async def` [CONFIRMED]
**Шаг 4, step_4_curator.md, строки 55–58 (`run_agents`).**
`run_agent_session(agent_id, messages)` — синхронная функция (в agents.py нет `async`), вызывается напрямую внутри `async def run_agents`. Это заблокирует event loop на время HTTP-запроса к Anthropic API. При двух агентах — два блокирующих вызова подряд. Не упадёт, но зависнет event loop. В продакшене при увеличении числа агентов станет критичным.

### 5. BUS_TOPIC_ID и SHOWCASE_TOPIC_ID — строки вместо int [CONFIRMED]
**Шаг 1, step_1_infra.md, строки 27–28.**
В `.env структура` BUS_TOPIC_ID записан как полный URL (`https://t.me/c/3968221945/3`), а не число. В step_3_agents.md строка 95: `BUS_TOPIC_ID = int(os.getenv("BUS_TOPIC_ID"))` — `int("https://t.me/...")` вызовет `ValueError` при запуске bus.py. Аналогично в step_4_curator.md строка 40. Агент-исполнитель получит неочевидный краш без объяснения причины.

### 6. Сценарий 1 (голосование агентов) не реализован, но тестируется [CONFIRMED]
**Шаг 4, step_4_curator.md, строка 136:** "Сценарий 1 задокументирован — даже если не реализован".
**Шаг 5, step_5_test.md, строки 28–38:** Тест 2 требует запустить Сценарий 1. Парсинг тегов `Предлагаю:` / `Поддерживаю` не написан ни в одном файле плана. Критерий готовности шага 5 требует выполнить "Тест 2 или 3 (хотя бы один)" — агент-исполнитель может попытаться запустить нереализованный тест и зависнуть.

### 7. Зависимость от внешней системы: Anthropic Managed Agents [LIKELY]
**Шаги 3, 4.** Managed Agents — это managed cloud-сервис Anthropic. Если сервис недоступен, в режиме preview, или отключён для аккаунта — весь шаг 3 и шаг 4 встанут без возможности продолжить. В плане нет fallback (например, обычный `client.messages.create` вместо managed session). Проверить доступность сервиса для конкретного API_KEY перед выполнением шага 3 не инструктируется.

### 8. Приватный канал `iwacado` — нет проверки доступа [LIKELY]
**Шаг 1, step_1_infra.md, строка 28:** `PRIVATE_CHANNEL=iwacado`.
**Шаг 2** предполагает что Telethon userbot является участником этого канала. Если аккаунт не подписан на канал — `client.get_entity("iwacado")` вернёт `ChannelPrivateError` или `UsernameNotOccupiedError`. В критериях готовности шага 2 нет проверки что именно userbot-аккаунт имеет доступ к каналу.

### 9. Отсутствие дедупликации: один и тот же пост может попасть в Showcase дважды [LIKELY]
**Шаг 4, step_4_curator.md, step_5_test.md.** При повторном запуске `curator/main.py` в тот же день (ручной перезапуск при отладке, сбой, тест) — агенты прочитают тот же канал, напишут в Bus те же сообщения, куратор опубликует в Showcase ещё один пост. Никакого state (отметки "уже публиковали сегодня") в плане нет. При тестировании это гарантированно произойдёт.

## Мелочи ([THEORETICAL])

### T1. Telegram rate limits при массовом постинге
Если агентов станет >5 и все постят в Bus одновременно — Telegram может временно ограничить бота (429). Для MVP с 2 агентами не актуально.

### T2. `msg.date` timezone-aware в новых версиях Telethon
В коде шага 2 используется `msg.date.replace(tzinfo=None)` для сравнения с `datetime.utcnow()`. В Telethon >=1.24 `msg.date` timezone-aware (UTC), `datetime.utcnow()` — naive. Может вызвать `TypeError: can't compare offset-naive and offset-aware`. Теоретически — зависит от версии.

### T3. `session.output` — недокументированное поле
В step_3_agents.md строка 83: `return session.output`. Структура ответа Managed Agents API не верифицирована в плане. Поле может называться иначе (`session.result`, `session.response.content`).
