# Reply-цепочки (вариант A) для hot-topics кластеризации

> Статус: done (2026-06-10)
> Дата: 2026-06-10
> Тип: фича (качество кластеров)

## Цель

Перед кластеризацией hot-topics склеивать reply-треды (и серии подряд идущих
сообщений одного автора) в «документы» и кластеризовать документы вместо
одиночных сообщений. Лечит три дефекта, найденных диагностикой 2026-06-10:
реакции («спасибо за лонгрид») кластеризуются отдельно от исходника по
мета-словарю; живые треды рвутся на «исходник» и «благодарности»; разные
разговоры склеиваются в мега-кластеры через сообщения-реакции.

  ~12 реакций — ОДИН документ → одна тема «смена работы», ссылка на 14067.

- Лайки/авторы коротких реакций (<80 символов, раньше выбрасывались целиком)

  + chain_cluster_stats(documents) -> {'msgs','likes','authors'}         [шаг 3]

Документ (контракт `build_chains`, фиксируется в шаге 2):
```python
{
  'messages':    list[dict],   # ВСЕ сообщения цепочки, sorted by created_at
  'substantive': list[dict],   # прошедшие флуд-фильтр (подмножество messages)
  'embedding':   list[float],  # length-weighted среднее по substantive
  'root':        dict,         # messages[0] — начало треда (анкор)
}
```

## Ключевые решения (зафиксированы с пользователем 2026-06-10)

1. Склейка = reply-связи (`metadata.reply_to_msg_id`) + серии: подряд идущие
   сообщения ОДНОГО автора с разрывом ≤ 300 секунд объединяются (склеивает
   части лонгридов, между которыми нет reply).
2. Эмбеддинг документа — среднее существующих векторов содержательных
   сообщений, взвешенное по длине текста. Без нового OpenAI-спенда.
3. `msgs` в дайджесте = только содержательные сообщения кластера;
   likes/authors в hotness — по ВСЕМ сообщениям цепочек (реакции дают вклад).
4. Документ кластеризуется только если в нём ≥1 содержательное сообщение
   (флуд-фильтр остаётся пер-сообщенчным, см. шаг 2).
5. Анкор кластера: самый ранний крепко привязанный документ
   (probability ≥ ANCHOR_MIN_PROBABILITY, fallback на самый ранний) → его
   `root`. Логика анкор-фикса ab6af26 переносится на уровень документов.
