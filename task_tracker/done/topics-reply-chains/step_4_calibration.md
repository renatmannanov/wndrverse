## Задача

Прогнать новый конвейер на boltalka/май (тот же срез, что в диагностике
2026-06-10) и проверить, что целевые дефекты ушли. Инструмент — временный
скрипт `tmp_inspect_chains.py` (по образцу диагностики: без LLM-вызовов,
печатает составы кластеров; УДАЛИТЬ в шаге 5).

Скрипт НЕ коммитить ни в один промежуточный коммит — он живёт только в
рабочей копии до шага 5 (там удаляется).

Скрипт печатает:
1. Воронку: fragments → docs (build_chains) → кластеров → шум.
2. Trace контрольного треда: документ, содержащий msg_id 14067 — должен
   содержать ТАКЖЕ 14069, 14070 и reply-ответы (14082, 14095, 14101…);
   `root` документа == 14067.
3. Для топ-10 кластеров: имя-заглушка, msgs/likes/authors, анкор (msg_id),
   тексты substantive-сообщений (по 130 символов).
4. Fallback-rate анкора: долю кластеров, где НИ ОДИН документ не прошёл
   `probability >= ANCHOR_MIN_PROBABILITY` (анкор взят fallback'ом «просто
   ранний»). Константа калибровалась на сообщениях; на документах
   распределение probability другое — если fallback-rate == 100%, «крепкость»
   молча отключилась: зафиксировать в progress.md и ПОДНЯТЬ ВОПРОС
   пользователю (порог НЕ крутить самостоятельно).

Оценка качества (записать вердикт в progress.md, по пунктам):
- [дефект 1] Отдельного «кластера благодарностей» (реакции на лонгрид) нет;
  реакции сидят в документе лонгрида.
- [дефект 2] Кластер «двух разговоров» (быть-увиденной + подкаст М/Ж,
  бывший rank#1) — распался или нет. Если НЕ распался, зафиксировать в
  progress.md как известное ограничение (reply-связи между этими разговорами
  реально есть/нет — посмотреть), НЕ крутить пороги ради него.
- [дефект 3] Анкоры топ-10 — корни тредов (не реакции, не стрэи).

Калибровка `min_cluster_size` (единственная ручка, которую МОЖНО крутить в
этом шаге): документов меньше, чем сообщений (~325 → ожидаемо ~150-250), и
«3 документа» — другая величина, чем «3 сообщения». Прогнать min_cluster_size
2 и 3. Правило выбора (детерминированное, без «по качеству»):
- если min_cluster_size=3 даёт ≥5 тем на boltalka/май → оставить 3;
- иначе → взять 2.
Итоговое значение + число тем при обоих значениях записать в progress.md и
зафиксировать комментарием в `build_topics` (как калибровку 2026-06-09).
Другие пороги (min_chars, min_authors, min_probability, SERIES_GAP_S,
ANCHOR_MIN_PROBABILITY) в этом шаге НЕ трогать.
