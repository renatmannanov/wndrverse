## Задача

Новый модуль `delivery/topics_render.py` — превращает список `TopicCluster` в
целевой текст. Строит t.me-ссылки. НЕ знает про кластеризацию/LLM.

### Контракт TopicCluster (ФИНАЛЬНЫЙ, единственный)

`brain.topics.build_topics` (шаг 5) отдаёт список таких dict-ов:

```python
{
  'name': str,                # название темы (LLM, по-русски)
  'msgs': int,                # число сообщений в кластере
  'anchor_channel_id': int,   # -100… форма (из якорного сообщения)
  'anchor_external_id': str,  # 'tg_-100…_<msg_id>' (из якорного сообщения)
}
```

ВАЖНО: поля `emoji` в контракте НЕТ. Эмодзи назначает РЕНДЕР по позиции в уже
отсортированном списке (фикс. палитра) — так LLM не выдумывает эмодзи и палитра
консистентна. brain.topics эмодзи не трогает.

Детали:
- **Палитра эмодзи** — фикс. список в модуле:
  `EMOJI = ['📈','🔮','📊','🔄','💹','💼','🚀','📉','🔍','📌','💡','🔥','⚡','🌱','🎯']`.
  Эмодзи темы = `EMOJI[i % len(EMOJI)]`, где i — индекс в отсортированном списке.
- `plural_msgs(n)`: учесть, что 11-14 → «сообщений» (несмотря на последнюю цифру
  1-4). Стандартное русское правило по `n % 100` и `n % 10`.

## Тесты

`tests/test_topics_render.py`:
- `tg_link(-1002924475859, 'tg_-1002924475859_9307') == 'https://t.me/c/2924475859/9307'`
- `tg_link(-1002924475859, 'bad') == ''` (не парсится).
- `tg_link(-1002924475859, 'wndr_chatname_415') == ''` (legacy без -100 → пусто).
- `plural_msgs(1)=='сообщение'`, `plural_msgs(3)=='сообщения'`,
  `plural_msgs(5)=='сообщений'`, `plural_msgs(12)=='сообщений'`,
  `plural_msgs(22)=='сообщения'`, `plural_msgs(11)=='сообщений'`.
- `render_topics` на 2 темах: содержит обе ссылки, обе строки `(N …)`, эмодзи из
  палитры по порядку (первая тема → 📈, вторая → 🔮).
