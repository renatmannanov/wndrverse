Я хочу подключить **Telegram-бота** к ядру `core/` так, чтобы он в реалтайме
писал новые сообщения из групп в нашу БД (`fragments`). Это **future**-задача
из плана `community-brain-mvp` (она там была явно отложена). Сейчас наступил
её черёд.

## Контекст — что уже сделано (только что закрылось)

Ядро `core/` готово и работает end-to-end:
- ingest (JSON-выгрузки telegram-gather) → store (postgres+pgvector) → enrich
  (embeddings) → brain (синтез дайджестов) → delivery (CLI, stdout)
- Полный план и прогресс: `task_tracker/done/community-brain-mvp/` (читай PLAN.md
  и progress.md ОБЯЗАТЕЛЬНО — там 9 шагов, learnings, грабли, PII-решение).
- Корпус: 6530 фрагментов (10 топиков WNDR), 6104 embedded.
- Дайджесты лежат в `data/digests/` (gitignored).

**Главное проектное решение под realtime — уже заложено:** `core/ingest/loaders.py`
содержит функцию `ingest(messages: list[dict]) -> dict` как **единый funnel** для
любого источника (сейчас файл, завтра бот). Бот должен звать именно её. Это
сознательная архитектура, не угадывание.

### Фаза 3 — НАПИСАТЬ ПЛАН

Используй скилл `/write-plan` — он знает наш формат. План положи в
`task_tracker/todo/realtime-bot-ingest/` со структурой:

```
realtime-bot-ingest/
├── PLAN.md          (мастер: цель, шаги, ключевые решения, критерии)
├── progress.md      (память: откуда смотреть, грабли, learnings)
├── step_1_*.md      (≤ 300 строк каждый)
├── ...
└── step_N_completion.md   (обязательный последний шаг)
```

Каждый step — с **проверяемыми командами**, не словами. Минимум что должно
быть в плане:

- Шаг про **адаптер** `bot_message → Fragment dict` (как normalize.py, но
  для python-telegram-bot/telethon-объектов). Это новый файл в
  `core/ingest/`, например `bot_adapter.py`.
- Шаг про **маппинг chat_id → topic** (явное решение из Фазы 2).
- Шаг про **подключение** к существующему боту: куда вставить вызов
  `ingest([fragment])` в обработчик нового сообщения.
- Шаг про **дедуп**: чтобы повторный приём того же `message_id` не
  плодил фрагменты (у нас есть `external_id`, но формат для бота надо
  выбрать — например `bot_{chat_id}_{message_id}`).
- Шаг про **тест на одной группе**: добавить бота, послать ~5 сообщений,
  убедиться что появились в БД с правильным topic и без дублей.
- Шаг про **handling edge cases**: edits, replies, media-only (без текста),
  служебные сообщения. По аналогии с `message_to_fragment` который их
  скипает.
- Шаг про **enrich/digest на боевых данных** одной группы после ~часа
  жизни (или сколько посчитаешь нужным).

В плане ОБЯЗАТЕЛЬНО раздел «Что НЕ в этом MVP» — иначе scope creep
гарантирован. Не делать в этом плане: разовую выгрузку через
telegram-gather API (это другая задача, отдельное окно), доставку
дайджестов обратно в TG, расписания.
